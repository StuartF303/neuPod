# Click-wheel protocol (iPod Classic 6G)

Source: Rockbox ipod6g reverse-engineering (`firmware/target/arm/s5l8702/`,
`ipod/button-clickwheel.c`) and the community 5G click-wheel teardown; see
[Design → Click wheel](design.md#click-wheel). Items marked **TBC** are unconfirmed on the 6G.

## Electrical

| Line | Direction | Notes |
|------|-----------|-------|
| CLK | wheel → host | open-drain, ~53 kHz, generated by the wheel |
| SDO | wheel → host | open-drain, frame data |
| SDI | host → wheel | init packet |
| 4th line | **TBC** | configured with the other three by the S5L8702; likely WAKE or enable |

- **18 kΩ pull-ups** on CLK/SDO, located on the wheel's own flex (5G teardown; verify on the 6G
  with a meter before adding board pull-ups).
- The wheel has its own 3.0 V LDO; 3.3 V from our board is fine.

## Frames (wheel → host)

The wheel streams **32-bit frames, LSB first**.

A frame `x` is valid when:

```c
(x & 0x800000FF) == 0x8000001A
```

| Bits | Field |
|------|-------|
| 0–7 | `0x1A` (frame marker, part of the validity check) |
| 8 | Select |
| 9 | Right |
| 10 | Left |
| 11 | Play |
| 12 | Menu |
| 16–22 | Finger position, 0–95 (3.75° per count, clockwise, 0 at Menu) |
| 30 | Finger on wheel |
| 31 | `1` (part of the validity check) |

## Host → wheel

The host sends one init packet, **`0x8000023A`**, at start-up and again after Hold is released.
This is the only host transmission Rockbox makes. The wheel replies with a `0x8000023A`-type
frame carrying button state in bits 16–20. Its low byte is `0x3A`, so the frame-validity check
above rejects it.

On the S5L8702 the packet is written to the WHEEL peripheral's TX register (`WHEELTX`) and the
hardware shifts it out.

## Hold

On Hold, Rockbox stops the wheel controller and drives all four lines low as GPIO. On release it
re-initialises the wheel and re-sends the init packet. neuPod should idle or power-gate the
wheel the same way to save battery.

## Scrolling (Rockbox constants)

| Constant | Value |
|----------|-------|
| Counts per revolution | 96 |
| Counts per list step | 4 |
| Untouched debounce | 150 ms |
| Repeat timeout | 250 ms |

These are Rockbox's UI tuning values, not protocol requirements.

## Open questions

**Host → wheel init packet: not documented anywhere in the open.** Plan (3 Nov 2026): capture all four wheel lines
on the donor iPod with the logic analyser from power-on (Rockbox boot). That shows which side drives SDI/SDO, the
clock source during the init packet, and its timing. Until then the UI is driven from the UART keys.


- Mapping of the four lines to GP19/26/27/28 (see [Phase 1 wiring](wiring-phase1.md)); measure
  with a logic analyser on the donor's stock board.
- Identity and function of the fourth line.
- Which edge of CLK data is valid on, and how frame boundaries are delimited.
- Whether the wheel or the host drives CLK while the init packet is sent.
- Pull-up location on the 6G (assumed wheel flex, as on the 5G).

Firmware: `app/include/clickwheel_frame.h` (decoder), `platforms/rp2350/hal/hal_input.c` (PIO
receiver), tests in `tests/`.
