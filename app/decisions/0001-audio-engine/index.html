    0001: Audio engine¶

    Status: Proposed (2026-11-21) · Owner: Audio engineer

    Context¶

    • Formats: FLAC up to 24/192, ALAC, MP3, AAC/M4A, WAV, Opus, Ogg Vorbis, on iOS and Android. A file the platform can't decode is listed greyed with the reason, and it never stops the queue.
    • True gapless between consecutive tracks, checked by a measured join test.
    • Queue: play, play next, add, reorder, clear. Seek. Shuffle and repeat stay in the Dart domain layer.
    • Background playback and interruptions: a call, headphones unplugged (becoming noisy), audio focus loss. The session side is in 0002.
    • No resampling or DSP in the app. Pass the file's sample rate through to an external DAC where the platform allows, and report what was achieved.
    • Play from an Android SAF content:// tree URI and from an iOS security-scoped bookmarked URL, not just plain paths.
    • No network connection at all, no analytics.
    • Licence compatible with distributing an MPL-2.0 app on both stores. Actively maintained.
    • Minimum OS (owner, 2026-11-21): iOS 18 and Android 10 (API 29). iOS 27 shipped on 14 September 2026. Every option below supports those versions.

    just_audio (with audio_service). The quickest route, and the API matches the queue we need. It fails the spec on iOS in two ways. First, it plays through AVQueuePlayer, and its tracker has open, unresolved reports of audible gaps between items on iOS 17 and later, including iOS 26 with FLAC. The maintainer's conclusion is that the cause is inside AVQueuePlayer ("mysterious behaviour of Apple's AVQueuePlayer", #1151). Second, iOS can't play Ogg through it at all. On Android it pins Media3 1.4.1 and offers no float or high-res output setting. An AVAudioEngine rewrite of the iOS side has been an open request since 2021 (#334) and has no delivery date.

    media_kit. The only off-the-shelf option that decodes all seven formats on both platforms, because it ships FFmpeg. Against it: no media session (it would need audio_service), no handling of interruptions or audio focus, mpv's own output and resampling chain, about 10 MB or more of LGPL native binaries fetched from GitHub at build time, LGPL relinking obligations in App Store builds, and 11 months without a pub release. It is the fallback if bundling Xiph and ALAC decoders ourselves proves too costly.

    flutter_soloud and audioplayers. Not music-player engines. audioplayers has no gapless queue. SoLoud is a game mixer and resamples by design.

    Custom thin plugin. On Android, Media3 does the work: gapless playlists, content://, audio focus, becoming noisy, and the session (0002). On iOS, AVAudioEngine scheduling makes gapless independent of AVQueuePlayer's behaviour. Bundled Xiph decoders close the Ogg gap that the system frameworks leave. The cost is native code for us to own on both platforms: route-change and engine-restart handling, seek by rescheduling, and position reporting.

    Decision¶

    Build a thin in-repo Flutter plugin (mobile/packages/neupod_audio, MPL-2.0) with a small Dart API: set queue, insert, move, remove, clear, play, pause, seek, skip, and streams of state, position, current index and format.

    • Android: androidx.media3:media3-exoplayer 1.11.x, with the player owned by a Media3 MediaSessionService (see 0002).
    • iOS: AVAudioEngine with one AVAudioPlayerNode. Decoding uses AVAudioFile for FLAC, ALAC, MP3, AAC and WAV, and bundled libogg, libopus and libvorbis for Ogg. Each track's PCM buffers are scheduled back-to-back. The session's preferred sample rate is set to the file's rate.

    Why: it is the only option that can meet gapless on iOS, and all seven formats on both platforms, without LGPL binaries or an unmaintained dependency. Media3 does most of the Android work and is maintained by Google.

    The phase-1 spike first runs the gapless join test on iOS with a plain AVQueuePlayer. If it passes for every format, the iOS side may use AVQueuePlayer for the system formats, which handles AirPlay and route changes for us, and keep AVAudioEngine only for Ogg.

    Consequences and risks¶

    • ALAC on Android isn't a platform format. It is missing from Android's supported-formats table, so it is device-dependent. Meeting the spec needs a bundled decoder. Either:
    • Media3's FFmpeg extension built with only alac. Google documents this path, but it is FFmpeg, LGPL-2.1, and we must build it from source.
    • Apple's open-source ALAC decoder (Apache-2.0) wrapped as a Media3 decoder. More code for us.

    Lead decision (2026-11-21): Apple's ALAC decoder (Apache-2.0), wrapped as a Media3 decoder. It avoids building and shipping LGPL FFmpeg, and the firmware already has a C port of the same decoder (app/third_party/alac/), which the plugin can reuse. FFmpeg with only alac stays the fallback. - Mixed sample rates on iOS. Scheduling on one AVAudioPlayerNode is sample-accurate only while the rate stays the same. An album that changes rate between tracks needs the engine reconfigured or a converter at the join, which can leave a gap (or resample). Spike case: two tracks at 44.1 and 48 kHz back-to-back. - Ogg Vorbis and Ogg Opus on iOS have no system decoder for apps. No Apple document lists them. A third-party test on the iOS 27 simulator found that AVFoundation demuxes Ogg but has no Vorbis decoder. The same project reported Ogg Opus working on iOS 27, then reverted that change a day later. Safari's Ogg support since iOS 18.4 is WebKit's own and isn't exposed to apps. We meet the spec only by bundling the Xiph decoders, about 1 MB, BSD-3. - 24-bit/192 kHz FLAC on Android. The platform FLAC decoder is documented only to 48 kHz, "no dither applied for 24-bit". If the spike shows real decoders fall short, add Media3's libflac extension (BSD, built from source), which outputs raw PCM on every API level. Whether 24-bit PCM reaches the AudioTrack or is reduced to 16-bit by DefaultAudioSink must be checked. We may need float output enabled. - Sample-rate passthrough and bit-perfect output. No option can guarantee these. The platforms limit them: - Android 10–13: the system mixer resamples everything to the output's rate, usually 48 kHz. - Android 14+: setPreferredMixerAttributes with MIXER_BEHAVIOR_BIT_PERFECT exists for USB devices only, and vendor HAL support is optional. - iOS: setPreferredSampleRate is only a hint. Some USB DACs follow it; reports differ on whether output goes above 48 kHz. - Bluetooth and AirPlay: always re-encoded or at a fixed rate.

    The format line must report the achieved output rate, never a claim. - MP3 and AAC gapless depends on encoder-delay metadata (LAME/Xing, iTunSMPB) being present and honoured. Files without it can't be gapless on any engine. - iOS AVAudioEngine stops on route and configuration changes, and the plugin must restart it and reschedule from the current frame. That is a source of bugs; test it on the device with Bluetooth, wired and AirPlay. - The Mac's toolchain is Xcode 26.5, which has no iOS 27 SDK or simulator, and phones in use run iOS 27. iOS 27 behaviour, such as Ogg in AVFoundation, can only be checked on a device, or after Xcode 27 is installed. Ask the owner. - We own native code in Kotlin and Swift. Media3 is Apache-2.0 and the Xiph libraries are BSD-3; both go on the Licences screen and in LICENSE.md.

    To verify in the phase 1 spike¶

    1. Gapless: run the generated two-track join fixture (FLAC 16/44.1, FLAC 24/96, ALAC, AAC with iTunSMPB, MP3 with LAME header, Opus, Vorbis, WAV) through the iOS AVQueuePlayer and AVAudioEngine variants and through Media3. Measure the sample offset at the join, not by ear. Pass means 0 samples of inserted silence.
    2. Play content:// FLAC from a persisted SAF tree grant on an API 29 emulator and an API 36 emulator, after an app restart.
    3. Play a FLAC from an iOS security-scoped bookmark to an iCloud Drive or external folder after an app relaunch, on the owner's iPhone.
    4. Decode every fixture in tests/assets/audio on both platforms. Record per format: played, or the exact error. Include 24/192 FLAC on Android using the platform decoder only, and ALAC on the emulator and a real Android phone.
    5. Android output encoding for 24-bit FLAC: log the AudioTrack encoding and sample rate. On an Android 14+ phone with a USB DAC, try setPreferredMixerAttributes(BIT_PERFECT) and record the result.
    6. iOS: set the preferred sample rate to 96 kHz with a USB DAC, and log AVAudioSession.sampleRate after activation.
    7. Check that the release Android manifest has no INTERNET permission, and that nothing in the plugin opens a socket. On iOS, record a network trace during playback (it should be empty).
    8. Build size delta of the Xiph decoders, and of the ALAC decoder option chosen.

    Phase 1 implementation (2026-11-22)¶

    Built as decided, in mobile/packages/neupod_audio (Pigeon 30.0.4 contract in pigeon/messages.dart). Where it differs from or defers part of the text above:

    • iOS schedules file segments, not hand-read buffers. Each track goes to the node with AVAudioPlayerNode.scheduleSegment(_:startingFrame:frameCount:at:); AVAudioFile reads and converts it on the engine's thread. Consecutive segments on one node join sample-accurately just as buffers do, with less code and no buffer pool to size. Only the current and the next track are scheduled. scheduleBuffer stays the path for the bundled Xiph decoders (Ogg, phase 4), which produce PCM themselves.
    • Mixed formats at a join: the next track is pre-scheduled only when its processing format (rate, channels) matches the connected one. Otherwise the engine is reconnected when the current track ends, which can leave a short gap. The join test in phase 4 measures both cases.
    • The AVQueuePlayer comparison spike was not run. Phase 1 needed one working path; AVAudioEngine is it. The measured join test (spike item 1) is the phase 4 item "Gapless, with the measured join test"; if AVQueuePlayer then proves gapless for every system format, switching the system formats to it is still open.
    • No network on Android, enforced in code as well as by the manifest: the player and the artwork loader use a data source that opens only content:// and file:// (LocalDataSource.kt), so Media3's HTTP, UDP, RTMP and data: sources are never reached.
    • The skip-back rule is native on both platforms (Media3's maxSeekToPreviousPositionMs = 3000; the same rule in AudioEngine.swift), because the lock screen's previous button reaches the engine without Dart.
    • Every setQueue carries a random queue id, echoed in every engine event, and the Dart player applies only events with its own id. So an event about an earlier queue, a stale empty snapshot, or a queue an earlier Flutter engine set while the Android service lived on, never moves the current one (mobile/lib/audio/neupod_player.dart). On Android the id rides in each item's metadata extras, so it lives in the session, not in the plugin.
    • iOS position after the system stops the engine: the node has no render time then, so the engine keeps a render anchor (position and CACurrentMediaTime when rendering last started or a gapless join happened) and extrapolates from it. A route or format change, or an interruption, records the true position and the next play reschedules from it. The unplug burst (a route change and a configuration change, in an undocumented order) is handled by one shared test in both handlers; the residual risk, if currentRoute lags the first notification, is in 0002. Engine events report isPlaying (sound now) apart from the play intent, so Dart does not extrapolate while playback is suppressed.
    • An unplayable entry never stops the queue: the engine reports the error with the entry, and the Dart player skips to the next one once.
    • On Android the session also prepares the player again whenever it is idle with an error from a track other than the current one (ErrorRecovery.kt). Without it, a play that retried the failed track, followed at once by the skip, could leave the player idle on the next track. The plugin decides from a MediaController's masked state, which cannot see the retry's error coming. This was a CI flake on PR #111, reproduced with a forced ordering and now covered by an integration test.
    • Not yet (later phases, seams left): Ogg on iOS, ALAC on Android, repeat-one gapless (repeat is a Dart rule, so the engine will need the mode to pre-schedule the same track), output-route reporting, measured sample-rate passthrough. The iOS session's preferred sample rate is already set to the file's rate as a hint.

    Later (noted in review, 2026-11-22)¶

    • Late scheduling of the next segment. Today the next track is scheduled as soon as the current one starts, so an edit to the queue's next entry reschedules the current track from its position, a small blip. Scheduling the next segment a few seconds before the join would make most edits free.
    • A debug-only PCM capture hook (a tap on the mixer on iOS, an AudioProcessor or TeeAudioProcessor on Android) for the phase 4 measured gapless join test.
    • The bundled test tones ship in the app (integration_test/assets/test_media/, declared as assets for the debug screen and the integration tests). A release blocker, tracked in PROGRESS.md.
