    Set-up notes¶

    • scripts/app/bootstrap-mac.sh --no-agent finishes cleanly. On the first run, brew install failed with "Cannot link ca-certificates" and then "Cannot link ruby", because Homebrew had left an old version of each package (and of libevent, libunistring, pcre2 and utf8proc) beside the new one. brew cleanup <formula> on each fixed it.
    • The temurin@17 cask runs a .pkg installer that needs the owner's password, which can't be typed at an ssh prompt without a terminal. It was run in a separate tmux window and the owner typed the password there.
    • iOS CI runs on GitHub-hosted macOS runners.

    Goldens (screenshot tests)¶

    The golden PNGs under mobile/test/ui/{components,screens,device}/goldens are made and compared on one machine only: the goldens job of .github/workflows/app.yml, on the GitHub-hosted macos-26 image (the label the ios job uses, never -latest). Text rasterises differently on Linux and on each macOS release: after the build Mac moved from macOS 26.5 to 27.2.1, every component and screen golden made on 26.5 failed there by 0.00 to 0.21 % of its pixels, all on glyph edges, while the runner (macOS 26.7.2) reproduced 144 of them byte for byte (2026-11-22). So a local Mac is not the reference.

    • In CI the goldens job runs flutter test test/ui/components test/ui/screens test/ui/device/goldens with NEUPOD_GOLDENS=compare and fails on any mismatch. On failure it uploads the golden-failures artifact (each failed golden's master, test and diff images). It is one of the jobs app-gate waits for.
    • The Linux check job runs the same tests without comparing pixels (overflow and exceptions still fail them).
    • Locally, flutter test doesn't compare golden pixels and prints a note saying so. NEUPOD_GOLDENS=compare flutter test ... compares them, but a failure of about 0.1 % on glyph edges can be your Mac, not the app. --update-goldens writes nothing outside GitHub Actions.
    • The job summary and the "Runner image" step log the image version (ImageVersion), which changes under the macos-26 label when GitHub updates the image. If every golden suddenly fails by about 0.1 % on glyph edges with no app change, compare it with the run that made the PNGs and regenerate.

    To regenerate (after an intended UI change, or an image update):

    1. Push the branch, then run the workflow by hand with the input set: gh workflow run app.yml --ref <branch> -f update_goldens=true (or Actions > app > Run workflow, tick update_goldens). Only the goldens job runs, about 2 minutes. CI never pushes commits.
    2. Download the goldens artifact: gh run download <run-id> -n goldens -D /tmp/goldens. It keeps the paths below mobile/test (ui/components/goldens, ui/screens/goldens, ui/device/goldens).
    3. Copy it over the tree: cp -R /tmp/goldens/. mobile/test/, check git status and look at every changed PNG (only the screens you meant to change should differ), then commit them (test(app): regenerate goldens ...) and push. The next PR run's goldens job compares against them.

    Never commit failures/ folders.
